# Объяснение контрольной работы 3

Проект: **тайм-трекер** - консольное C++ приложение для учета рабочего времени по задачам.

Главная идея третьей работы: показать не просто один файл с кодом, а нормальную модульную структуру проекта на C++ с заголовочными файлами, реализациями, CMake-сборкой и несколькими классами, каждый из которых отвечает за свою часть системы.

## Что сказать в начале

В этой работе проект был оформлен как полноценное консольное приложение. Код разделен на модули:

- модели данных: задача и рабочая сессия;
- бизнес-логика: управление задачами и таймером;
- хранение данных: чтение и запись CSV-файлов;
- вывод отчетов;
- пользовательский интерфейс в консоли.

То есть программа построена так, чтобы ее можно было развивать дальше: добавлять новые отчеты, менять способ хранения данных или заменить консольный интерфейс на другой.

## Для чего нужны папки

`include/` - заголовочные файлы. В них описаны классы, структуры и функции: какие методы есть, какие данные хранит класс, какой интерфейс доступен другим частям программы.

`src/` - файлы реализации. Здесь находится код методов, то есть как именно работают функции, объявленные в `include/`.

`data/` - локальное хранилище программы. В CSV-файлах сохраняются задачи и рабочие сессии, чтобы данные не пропадали после закрытия приложения.

`CMakeLists.txt` - инструкция для CMake: какие `.cpp` файлы собрать, какой стандарт C++ использовать и где искать заголовочные файлы.

`report.html` и `report.pdf` - отчет по практической работе.

`README.md` - краткое описание проекта, сборки и запуска.

`run.cmd` - удобный скрипт запуска на Windows.

## Как собирается проект

Файл `CMakeLists.txt` задает:

- минимальную версию CMake;
- название проекта `TimeTracker`;
- стандарт C++17;
- исполняемый файл `time_tracker`;
- список исходных файлов из `src/`;
- путь к заголовочным файлам `include/`.

Команды сборки:

```sh
cmake -S . -B build
cmake --build build
```

После сборки появляется исполняемый файл `time_tracker` или `time_tracker.exe`.

## Как запускается программа

Точка входа находится в `src/main.cpp`.

Последовательность работы:

1. Создается `TaskManager` для управления задачами.
2. Создается `Storage`, который работает с папкой `data`.
3. Из файлов загружаются сохраненные задачи.
4. Создается `TimeTracker`, который отвечает за запуск и остановку таймера.
5. Из файлов загружаются сохраненные рабочие сессии.
6. Создается `ConsoleUI`.
7. Запускается консольное меню методом `ui.run()`.

## Основные классы и файлы

### `Task.h` и `Task.cpp`

`Task` - структура задачи.

Поля:

- `id` - уникальный номер задачи;
- `title` - название задачи;
- `description` - описание задачи;
- `status` - состояние задачи: активная или архивная.

`TaskStatus` - перечисление статусов:

- `Active` - задача активна;
- `Archived` - задача отправлена в архив.

Функции:

- `toString(TaskStatus status)` - переводит статус в строку для вывода и сохранения;
- `taskStatusFromString(const std::string& value)` - переводит строку обратно в статус при загрузке из файла.

Что сказать: этот модуль описывает одну задачу как объект предметной области. Он не управляет списком задач, а только задает форму одной задачи.

### `TimeSession.h` и `TimeSession.cpp`

`TimeSession` - структура рабочей сессии, то есть промежутка времени, когда пользователь работал над задачей.

Поля:

- `id` - уникальный номер сессии;
- `taskId` - номер задачи, к которой относится сессия;
- `startTime` - время начала;
- `endTime` - время окончания;
- `active` - признак, идет ли сессия сейчас.

Функция:

- `durationSeconds()` - считает длительность сессии в секундах.

Если сессия активна, длительность считается от `startTime` до текущего времени. Если сессия завершена, длительность считается от `startTime` до `endTime`.

Что сказать: этот модуль нужен, чтобы отдельно хранить историю работы по задачам. Одна задача может иметь много рабочих сессий.

### `TaskManager.h` и `TaskManager.cpp`

`TaskManager` - класс для управления задачами.

Внутри хранит:

- `std::vector<Task> tasks_` - список всех задач.

Основные методы:

- `addTask(title, description)` - создает новую задачу и возвращает ее `id`;
- `archiveTask(taskId)` - переводит задачу в архив;
- `tasks()` - возвращает список задач для просмотра;
- `findTask(taskId)` - ищет задачу по номеру;
- `replaceTasks(loadedTasks)` - заменяет текущий список задач на загруженный из файла;
- `nextId()` - приватный метод, который вычисляет следующий свободный номер задачи.

Что сказать: `TaskManager` отделяет логику работы с задачами от интерфейса. Консольное меню не хранит задачи само, а обращается к этому классу.

### `TimeTracker.h` и `TimeTracker.cpp`

`TimeTracker` - класс для учета времени.

Внутри хранит:

- ссылку на `TaskManager`, чтобы проверять существование задач;
- `std::vector<TimeSession> sessions_` - список рабочих сессий.

Основные методы:

- `start(taskId)` - запускает таймер по задаче;
- `stop()` - останавливает активный таймер;
- `sessions()` - возвращает список всех сессий;
- `activeSession()` - ищет текущую активную сессию;
- `replaceSessions(loadedSessions)` - загружает сессии из файла;
- `nextId()` - приватный метод для получения следующего номера сессии.

Особенность: нельзя запустить второй таймер, пока уже есть активная сессия. Также нельзя запустить таймер по несуществующей или архивной задаче.

Что сказать: `TimeTracker` отвечает только за таймеры и рабочие сессии. Он использует `TaskManager`, но не занимается созданием задач.

### `Storage.h` и `Storage.cpp`

`Storage` - класс для сохранения и загрузки данных.

Основные методы:

- `loadTasks()` - загружает задачи из `data/tasks.csv`;
- `loadSessions()` - загружает рабочие сессии из `data/sessions.csv`;
- `saveTasks(tasks)` - сохраняет задачи;
- `saveSessions(sessions)` - сохраняет сессии;
- `tasksPath()` - формирует путь к файлу задач;
- `sessionsPath()` - формирует путь к файлу сессий.

Дополнительные функции внутри `Storage.cpp`:

- `toUnixSeconds(...)` - переводит время в число секунд для записи в CSV;
- `fromUnixSeconds(...)` - переводит число секунд обратно во время.

Что сказать: `Storage` реализует паттерн Repository в простом виде. Остальная программа не знает, как именно данные записываются в файлы. Она просто вызывает методы сохранения и загрузки.

### `ReportService.h` и `ReportService.cpp`

`ReportService` - класс для формирования отчета.

Основные методы:

- `totalSecondsByTask(sessions)` - считает суммарное время по каждой задаче;
- `printReport(tasks, sessions)` - печатает отчет в консоль.

Как работает отчет:

1. Берутся все завершенные сессии.
2. Для каждой сессии время добавляется к общей сумме по `taskId`.
3. Для каждой задачи выводится количество часов, минут и секунд.

Что сказать: отчет вынесен в отдельный класс, чтобы не смешивать расчеты с консольным меню и хранением данных.

### `ConsoleUI.h` и `ConsoleUI.cpp`

`ConsoleUI` - консольный интерфейс пользователя.

Внутри использует:

- `TaskManager` - для задач;
- `TimeTracker` - для таймеров;
- `Storage` - для сохранения данных;
- `ReportService` - для вывода отчета.

Основные методы:

- `run()` - главный цикл меню;
- `addTask()` - запросить название и описание, затем создать задачу;
- `listTasks()` - вывести список задач;
- `archiveTask()` - архивировать задачу по номеру;
- `startTimer()` - запустить таймер по задаче;
- `stopTimer()` - остановить активный таймер;
- `showHistory()` - вывести историю рабочих сессий;
- `save()` - сохранить задачи и сессии в CSV-файлы.

Вспомогательная функция:

- `readInt()` - читает число из консоли и очищает ввод.

Что сказать: `ConsoleUI` является фасадом для пользователя. Он объединяет несколько внутренних классов и дает простое меню.

### `main.cpp`

`main.cpp` - точка входа в приложение.

Он не содержит основную бизнес-логику. Его задача - создать нужные объекты, загрузить данные и запустить интерфейс.

Примерная схема:

```text
main
 -> TaskManager
 -> Storage
 -> загрузка задач
 -> TimeTracker
 -> загрузка сессий
 -> ConsoleUI
 -> run()
```

Что сказать: `main.cpp` специально маленький, потому что вся логика разнесена по отдельным классам.

## Как данные проходят через программу

Пример создания задачи:

1. Пользователь выбирает пункт меню `Add task`.
2. `ConsoleUI` считывает название и описание.
3. `ConsoleUI` вызывает `TaskManager::addTask`.
4. `TaskManager` создает объект `Task` и добавляет его в список.
5. При выходе `ConsoleUI::save` сохраняет задачи через `Storage`.

Пример запуска таймера:

1. Пользователь выбирает `Start timer`.
2. `ConsoleUI` просит номер задачи.
3. `TimeTracker::start` проверяет, что задача существует и активна.
4. Создается новая `TimeSession` с текущим временем.
5. Сессия помечается как активная.

Пример остановки таймера:

1. Пользователь выбирает `Stop timer`.
2. `TimeTracker::stop` ищет активную сессию.
3. В сессию записывается время окончания.
4. Сессия становится неактивной.
5. Пользователь видит длительность в секундах.

Пример отчета:

1. `ConsoleUI` вызывает `ReportService::printReport`.
2. `ReportService` проходит по завершенным сессиям.
3. Время группируется по задачам.
4. На экран выводится суммарное время по каждой задаче.

## Паттерны и архитектурные идеи

В работе можно упомянуть несколько паттернов:

`Facade` - `ConsoleUI` скрывает работу нескольких подсистем за простым консольным меню.

`Repository` - `Storage` отделяет хранение данных от бизнес-логики.

`Service` - `ReportService` выполняет отдельную сервисную задачу: расчет и вывод отчета.

Также есть разделение ответственности:

- `Task` только хранит данные задачи;
- `TaskManager` управляет задачами;
- `TimeTracker` управляет сессиями времени;
- `Storage` работает с файлами;
- `ReportService` считает отчет;
- `ConsoleUI` общается с пользователем.

## Возможные вопросы и ответы

**Почему код разделен на `.h` и `.cpp`?**

Чтобы отделить интерфейс от реализации. В `.h` видно, что умеет класс, а в `.cpp` написано, как именно он это делает.

**Почему нужен `TaskManager`, если есть `Task`?**

`Task` описывает одну задачу, а `TaskManager` управляет списком задач: создает, ищет и архивирует.

**Почему `TimeTracker` хранит ссылку на `TaskManager`?**

Чтобы перед запуском таймера проверить, существует ли задача и не находится ли она в архиве.

**Почему хранение вынесено в `Storage`?**

Чтобы бизнес-логика не зависела от формата файлов. Если потом заменить CSV на базу данных, менять в основном нужно будет только `Storage`.

**Почему отчет вынесен в `ReportService`?**

Потому что расчет суммарного времени - отдельная логика, и ее удобнее держать отдельно от меню.

**Что будет, если запустить второй таймер?**

`TimeTracker::start` вернет `false`, потому что в программе разрешена только одна активная сессия одновременно.

**Что сохраняется в CSV?**

В `tasks.csv` сохраняются задачи, а в `sessions.csv` - рабочие сессии с временем начала, окончания и признаком активности.
